# 2.0.2 普通权限存储修复

本轮针对实际用户环境中“Permission denied”和“Cannot write user data”修复，日期 2026-11-25。

- 创建目录和文件读写统一使用 Unicode Win32 API，保存错误带具体路径、Windows 错误码和系统原因。
- 当前目录无法创建、写入或原子替换文件时，依次尝试独立备用目录；回退保存完整班级和全部姓名，而不只保存设置。
- 优先使用用户本地数据目录，备用为 EXE 旁的 `data/<版本数据目录>`、用户漫游目录、文档目录。
- 保存成功后使用该目录继续读写；重启选择最近成功保存的配置，避免重新读取旧设置。
- 短暂文件占用会有限重试。写入失败不会覆盖原文件，不修改目录 ACL、加密或系统安全设置。
- 初次启动尚无配置时直接使用空状态，再载入专用版内置名单；不因不可访问的空系统目录而阻止启动。
- 拖动位置保存失败不会反复弹出模态窗口。全部目录无法保存时仍可继续本次点名，托盘仅提示一次；主动编辑名单的保存失败仍明确报告。

## 已验证

- 在实际 Windows 用户环境复现了原生进程写入系统数据目录返回错误 5。
- 两个专用版以普通用户令牌运行，核对 `TokenElevation=0`；各连续 14 次拖动无模态报错。
- 实际保存抽取模式，退出并重新启动，按钮位置和设置保留。
- 两份名单逐条比对，48 / 53 条记录完整；原有系统目录中的文件哈希保持不变。
- 核心测试覆盖设置文件独占锁下回退、完整名单和重复记录迁移、失败目录保留原文件、重启选择最近成功目录、所有目录不可用的错误报告。
- 原有导入和功能 UI 回归通过，包括锁定设置文件且菜单打开时退出、重启和首次设置。

移动便携版本时，应连同软件旁的 `data` 文件夹一起复制。实体触屏与其他系统兼容范围沿用 2.0.1 的限制说明。
