# ClassRollCall 2.0 — 完整项目开发规格

**项目类型：** Windows 原生桌面点名工具  
**开发语言：** C++17  
**目标平台：** Windows 7 SP1 / Windows 10 / Windows 11  
**核心要求：** 单 EXE、免安装、低内存、低 CPU、完全离线。

## 2. 产品定位

ClassRollCall 2.0 是一个专门用于课堂点名的轻量级悬浮工具。

使用场景：
- 教师在 Windows 电脑上播放 PPT 时使用。
- 鸿合智慧黑板及其他 Windows 触摸屏设备。
- 鼠标、触摸屏均可操作。
- 支持多个班级名单。
- 教师不需要学习复杂操作。

设计原则：

- 不做大型管理面板。
- 不做复杂主题编辑器。
- 不做联网功能。
- 不做账号系统。
- 不做数据库服务。
- 不做复杂统计。
- 不增加没有实际使用价值的功能。

**最重要：平时屏幕上只显示一个小型半透明悬浮按钮。**

## 4. UI 设计规范

### 4.1 整体风格

采用 Windows 11 Fluent Design 的简化风格。

视觉特征：

- 圆角。
- 柔和阴影。
- 半透明材质。
- 简洁图标。
- Segoe UI 字体。
- 中文自动回退到系统中文字体。
- 自动跟随 Windows 浅色 / 深色主题。
- 动画简洁、自然。

不使用实时桌面模糊、大面积渐变、复杂背景图片和高成本视觉特效。

Win7 下使用相同的自绘风格降级显示，不要求实现 Win11 独有的系统材质。

### 4.2 悬浮按钮

这是程序最重要的界面。

必须保留原版悬浮按钮的使用逻辑。

默认状态：
- 屏幕上只有一个悬浮按钮。
- 默认透明度约 50%。
- 圆角或圆形设计。
- 默认置顶。
- 不显示任务栏按钮。
- 不遮挡正常教学操作。
- 默认出现在屏幕右下区域。
- 支持鼠标拖动和触摸拖动。
- 记住上次位置。

点击状态：
- 点击后透明度提高到约 95%。
- 给出明确的视觉反馈。
- 开始随机抽取。
- 抽取结束后恢复半透明。

建议尺寸为 48～54 DIP，实际像素尺寸随 DPI 缩放。

按钮外形、图标和原版设计应先参考原项目源代码，不要擅自改成常驻控制面板。

### 4.3 抽取动画

点击按钮后：

1. 中央出现姓名快速滚动动画。
2. 动画持续约 0.8～1.2 秒。
3. 停止后显示最终抽中的姓名。
4. 姓名使用较大字号。
5. 弹窗位于悬浮按钮所在显示器的屏幕中央。
6. 最终姓名显示约 3 秒。
7. 弹窗淡出。
8. 悬浮按钮恢复默认半透明。

中央弹窗采用 Win11 风格的半透明圆角卡片、柔和阴影和清晰文字。

不做持续实时模糊，不做全屏高成本动画。

弹窗默认不拦截教师的其他操作。

### 4.4 右键和触摸菜单

鼠标右键打开菜单。

触摸长按约 500ms 打开菜单。

菜单内容：

- 切换班级
- 管理班级名单
- 导入名单
- 抽取模式
  - 均衡抽取
  - 完全随机
- 开机自动启动
- 重置悬浮按钮位置
- 关于
- 退出

菜单也要适配触摸屏，不能依赖鼠标悬停。

### 4.5 系统托盘

保留原版托盘功能：

- 显示托盘图标。
- 双击托盘图标切换悬浮按钮显示状态。
- 右键托盘图标打开快捷菜单。
- 支持退出程序。
- 不创建多余后台进程。

## 5. DPI 高分辨率适配

这是本次开发的重点，必须从底层正确实现。

禁止直接将界面尺寸和窗口位置全部写死为物理像素。

统一采用 DIP 逻辑尺寸。

转换公式：

`实际像素 = DIP × DPI / 96`

### 5.1 支持缩放比例

必须测试：

- 100%
- 125%
- 150%
- 175%
- 200%

### 5.2 显示分辨率

测试：

- 1920×1080
- 2560×1440
- 3840×2160

### 5.3 多显示器

必须支持：

- 不同分辨率显示器。
- 不同 DPI 显示器。
- 悬浮按钮跨屏移动。
- 跨屏后重新计算窗口尺寸。
- 保存按钮所在显示器及逻辑位置。
- 显示器移除后自动恢复到主屏幕。
- 按钮不得跑出可用工作区。

### 5.4 DPI API

根据系统版本降级：

- Windows 7：System DPI Awareness。
- Windows 8.1：Per-Monitor DPI Awareness V1。
- Windows 10 1607：Per-Monitor V1。
- Windows 10 1703 及以上、Windows 11：优先 Per-Monitor V2。

Manifest 同时配置新旧 DPI 声明。

动态检测 API，正确处理 `WM_DPICHANGED`。

Windows 7 不具备真正的 Per-Monitor DPI V1/V2 能力，因此不承诺其跨不同 DPI 显示器的动态缩放体验；至少保证系统 DPI 下显示正常。

所有窗口、按钮、文字、边距、触摸命中区域和弹窗均必须同步缩放。

## 6. 触摸屏适配

鸿合智慧黑板等设备必须能够直接使用。

实现要求：

- 支持鼠标点击。
- 支持手指点击。
- 支持触摸拖动。
- 支持触摸长按菜单。
- 点击区域至少 48 DIP。
- 不依赖鼠标悬停。
- 避免触摸事件和系统模拟鼠标事件重复触发。

优先使用：
- Windows 8 及以上：WM_POINTER。
- Windows 7：WM_TOUCH。

点击与拖动需要区分：

- 按下后移动距离未超过阈值，松开时判定为点击。
- 移动超过约 6 DIP，判定为拖动。
- 长按达到约 500ms，打开快捷菜单。

禁止一次触摸同时触发抽取和拖动。

## 7. 点名核心算法

只保留两种模式。

### 7.1 均衡抽取（默认）

要求：

1. 将班级全部学生索引放入数组。
2. 使用 Fisher-Yates 算法洗牌。
3. 每次抽取数组中的下一个学生。
4. 一轮内不会重复。
5. 全部抽取完毕后重新洗牌。
6. 更换班级或修改名单后重置抽取序列。

保证一轮内每个人都能被抽到一次。

### 7.2 完全随机

每次点击独立进行均匀随机抽取。

允许重复抽中同一个人，不保证每个人在一轮内都出现。

### 7.3 随机数

使用可靠的系统随机种子初始化随机引擎。

不需要密码学级别随机数，但不能使用简单的 `rand() % n`。

### 7.4 异常处理

- 名单为空：提示导入名单。
- 名单只有一个人：正常抽取。
- 名单重复：按独立记录处理，不擅自删除。
- 名单修改：重置均衡抽取序列。
- 切换班级：使用对应班级名单。

## 8. 多班级名单管理

必须支持多个班级独立保存。

例如：

- 高二2班
- 高二4班
- 高三1班

### 8.1 管理功能

支持：

- 新增班级。
- 导入班级。
- 切换班级。
- 修改班级名称。
- 删除班级。
- 显示各班人数。
- 记住上次使用的班级。

### 8.2 导入文件命名

默认将文件名作为班级名称。

例如：

`高二2班.xlsx` → 高二2班

`高二4班.xlsx` → 高二4班

允许修改名称。

如果存在同名班级，必须让用户选择重命名、替换或取消，不允许静默覆盖。

### 8.3 数据存储

使用 Windows 用户本地数据目录：

`%LOCALAPPDATA%\ClassRollCall\`

建议结构：

```text
ClassRollCall/
├── settings.ini
├── classes.ini
└── rosters/
    ├── class_001.txt
    ├── class_002.txt
    └── class_003.txt
```

名单采用 UTF-8 编码，一行一个学生。

配置记录：

- 当前班级。
- 抽取模式。
- 悬浮按钮位置。
- 开机启动状态。
- 主题模式。
- 必要的窗口配置。

不需要数据库。

保存时采用临时文件加原子替换，避免意外退出导致名单损坏。

## 9. 名单导入系统

这是本次最重要的功能升级。

目标：教师不需要提前整理名单，尽可能直接导入现有文件。

必须支持：

| 格式 | 扩展名 |
|---|---|
| 普通文本 | .txt |
| 逗号分隔 | .csv |
| Excel 97-2003 | .xls |
| Excel 新格式 | .xlsx |
| Word 文档 | .docx |
| 剪贴板 | 直接粘贴 |

同时支持将文件直接拖到程序上导入。

### 9.1 TXT

- 一行一个名字。
- 自动删除空白行。
- 去除首尾空格。
- 自动处理 BOM。
- 支持常见中文编码。

### 9.2 CSV

自动识别：

- UTF-8。
- UTF-8 BOM。
- UTF-16 LE / BE。
- GBK / GB18030。
- 逗号、制表符、分号等分隔符。

支持 CSV 引号转义规则。

支持多列数据。

### 9.3 XLS

使用轻量级 XLS 读取库，例如 libxls 1.5 及以上稳定版本。

要求：

- 读取工作表。
- 读取单元格。
- 支持中文。
- 支持多列。
- 识别姓名列。
- 支持选择工作表。

禁止调用 Excel COM 或要求安装 Office。

### 9.4 XLSX

采用 ZIP + XML 解析方案。

可以使用轻量 ZIP 库和 XML 库。

必须支持：

- workbook.xml。
- 工作表关系文件。
- sharedStrings.xml。
- inline strings。
- 普通单元格。
- 多工作表。
- 中文姓名。
- 多列数据。
- 空白行处理。

不执行宏，不执行公式。公式单元格只读取文件中已有的缓存结果。

### 9.5 DOCX

采用 ZIP + XML 解析。

支持：

- 普通段落。
- Word 表格。
- 多行文本。
- 多列姓名。
- 中文内容。

默认提取正文中的段落和表格。

如果存在表格，允许在预览中选择姓名列。

不需要支持旧版 `.doc`，本版本只要求 `.docx`。

### 9.6 剪贴板

支持：

- 从 Excel 复制一列直接粘贴。
- 从 Word 复制名单。
- 从网页复制名单。
- 从普通文本复制名单。
- 从其他表格复制多列数据。

优先读取 Unicode 文本。

提供简单粘贴窗口，允许预览和确认。

### 9.7 自动识别姓名列

常见表格：

| 学号 | 姓名 | 性别 | 班级 |
|---|---|---|---|
| 001 | 张三 | 男 | 2班 |
| 002 | 李四 | 女 | 2班 |

自动识别：

- 姓名
- 学生姓名
- 名字
- 学生
- Name
- Student Name

如果无法确定姓名列，必须显示预览，让用户选择。

不得直接将学号、性别、班级等信息全部混入点名名单。

### 9.8 导入预览

导入前显示：

- 文件名称。
- 工作表名称（如果是 Excel）。
- 识别出的姓名列。
- 识别到的人数。
- 姓名预览。
- 重复记录提示。
- 空白记录数量。

支持：

- 自动识别。
- 手动选择姓名列。
- 更换工作表。
- 确认导入。
- 取消导入。

重复姓名默认保留，允许用户选择去重。

### 9.9 多文件导入

支持一次选择多个文件。

每个文件默认创建一个独立班级。

例如同时选择：

- 高二2班.xlsx
- 高二4班.xlsx
- 高三1班.docx

导入后分别生成三个班级。

### 9.10 文件解析安全

- 不执行宏。
- 不执行公式。
- 不访问网络资源。
- XML 禁止外部实体和 DTD。
- ZIP 解压设置合理大小限制，防止 ZIP Bomb。
- 损坏文件必须给出错误提示，不能导致程序崩溃。
- 解析完成后及时释放临时内存。

推荐第三方库：

- libxls：读取旧版 XLS，使用维护中的稳定版本。
- miniz：ZIP 解析。
- pugixml：XML 解析。

第三方库全部静态编译，保留许可证文件，记录版本和来源。

不允许引入 LibreOffice、Office、Python 或浏览器内核作为解析依赖。

首次运行时，如果不存在配置文件，显示简单设置窗口。

允许一次导入多个文件，也允许跳过。

第三部分：完成设置。

点击完成后：

- 保存配置。

- 显示悬浮按钮。
- 不再打开主窗口。

以后直接运行程序就显示悬浮按钮。

默认跟随 Windows 主题。

支持：

- 浅色模式。
- 深色模式。

## 12. 性能要求

低性能开销和低内存占用是核心要求。

目标指标：

| 指标 | 目标 |
|---|---|
| 空闲 CPU | 接近 0%，不进行持续轮询 |
| 空闲内存工作集 | 尽量不超过 20 MB |
| 常规导入峰值 | 尽量不超过 80 MB |
| EXE 体积 | 目标不超过 15 MB |
| 网络请求 | 0 |
| 后台常驻工作线程 | 0 |
| 数据库 | 无 |

以上为优化目标，必须以实际 Release 构建测试为准。

实现原则：

1. 单进程。
2. 一个主要 UI 消息循环。
3. 空闲时不运行动画定时器。
4. 不使用高频轮询。
5. 不持续刷新透明窗口。
6. 只在窗口状态变化时重新绘制。
7. 只在抽取动画期间运行短时定时器。
8. 不保留不必要的文件解析缓存。
9. 导入完成后释放临时对象。
10. 不创建无用后台线程。

动画建议 30 FPS 即可，不追求高帧率。

悬浮按钮平时静止，不产生持续 GPU 或 CPU 工作。
